# Banking Ops Portal

Внутрішній портал банківських операцій (fullstack pet-проєкт), сфокусований на безпечних робочих процесах:
- життєвий цикл заявок
- погодження за ролями
- аудит дій
- JWT + OAuth2
- кеш і rate limiting через Redis
- Docker + CI-пайплайни

## Технологічний стек
- Backend: FastAPI
- Frontend: React + TypeScript
- БД: PostgreSQL
- Кеш/брокер: Redis
- Інфраструктура: Docker Compose, GitHub Actions, GitLab CI

## Що реалізовано
- Базовий каркас бекенду на FastAPI з health-ендпоінтами.
- Підготовлена структура для auth/workflow/ops модулів.
- Початкова fullstack-архітектура під внутрішній portal use-case.
- Готовий roadmap поетапної реалізації функціоналу.

## Архітектура (high-level)
- `backend/` — API, доменні моделі, бізнес-логіка, інтеграції
- `frontend/` — інтерфейс операторів/менеджерів, дашборди заявок
- `infra/` — Docker Compose, CI/CD конфігурація
- `docs/` — runbook, архітектурні нотатки, API-описи

## Локальний запуск
1. Підготуй Python 3.12+ та Node.js 20+.
2. Для бекенду встанови залежності та запусти API.
3. Для фронтенду встанови `npm` залежності і стартуй dev-сервер.

Приклад (бекенд):
```bash
pip install -r requirements.txt
python -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

## Запуск через Docker
```bash
docker compose up --build
```

## Швидкі перевірки
- `GET /api/v1/health`
- `GET /api/v1/ready`
- Перевірка авторизації та ролей через API-клієнт
- Перевірка базового workflow заявок (create -> approve/reject -> audit)

## Чому цей проєкт корисний для портфоліо
- Демонструє роботу з доменною логікою у фінтех-контексті.
- Показує, як будувати безпечні workflow зі слідами аудиту.
- Підкреслює готовність до командної розробки через CI та документацію.

## Roadmap комітів (0 -> N)
0. Ініціалізація структури репозиторію
1. Каркас бекенду + залежності
2. Авторизація (JWT + RBAC)
3. Доменні моделі операцій
4. API workflow для заявок
5. Аудит-лог + security middleware
6. Redis-кеш + обмеження частоти запитів
7. Каркас фронтенду
8. Авторизація на фронтенді + дошки заявок
9. Повний Docker Compose стек
10. Тести + CI (GitHub Actions + gitlab-ci.yml)
11. Полірування документації + runbook

## План наступних покращень
- Деталізувати моделі заявок і матрицю ролей.
- Додати інтеграційні тести критичних workflow-гілок.
